Scripts and libraries

Every .lua file directly inside the script root is examined once at startup and again whenever anything in the directory changes.

A script returns a table carrying any of four hooks. The engine calls them method-style, so self is the script's own table — that is where a scene keeps its state.

local scene = {}

function scene:init()          -- once, before the first frame
function scene:update(dt)      -- every frame, dt in seconds
function scene:draw()          -- every frame, after update
function scene:shutdown()      -- on exit, and before a reload

return scene

Everything else is a library: available through require("name"), never run by the frame loop. A file is a library when any of these is true.

ConditionWhy
Returns a non-tableA helper returning a function, or nothing, has no hooks to call.
M.__index == MIt is a class. Its init/update/draw are instance methods for a scene to call on objects made with M.new(), not frame hooks.
M.library = trueSaid outright, for anything the rules above miss.

Errors are caught and printed with a traceback. The offending script is disabled — it stops running rather than spamming the frame loop — and revived the moment its file changes. A typo never takes the window down.

Hot reload watches the file set as well as timestamps, so a script added, edited, or deleted while the app runs is picked up within half a second, shutdown and init included.

Conventions

Three rules that hold across the whole surface.

Vectors go in three spellings. Write whichever reads best at the call site; they are all read the same way.

position = { 1, 2, 3 }
position = { x = 1, y = 2, z = 3 }
scale    = 2.0                      -- a bare number means all three
color    = { r = 0.9, g = 0.3, b = 0.2 }   -- colours use r/g/b

Vectors come back as three values, not a table, so they drop straight into locals.

local x, y, z = camera:getPosition()
local w, h, d = model:size()

Coordinates are right-handed, Y up. The camera looks down −Z at yaw 0, pitch 0. Angles are always degrees.

Engine.log

Engine.log(...)

Prints its arguments to stdout behind a [lua] prefix, joined by tabs. Anything that tostring handles is accepted.

It joins; it does not format. Placeholders come out literally — wrap in string.format first.

Engine.model

glTF 2.0, both .gltf and .glb. Node hierarchy, PBR base colour, and embedded or external textures.

Engine.model.load(path, options)Modelinit() only

Loading is synchronous and a large map takes a moment, so it belongs in init(), never in update(). The renderer caches by path and options, so a hot reload re-uses what is already on the GPU instead of re-parsing the file.

recenter
move the bounding-box centre to the origin = false
scale
uniform scale baked into every part = 1.0
generateNormals
flat normals for parts that ship none = true
textures
decode and upload images = true
verbose
print a summary line on load = true
collision
keep the triangles on the CPU so the model can be raycast = true
self.map = Engine.model.load("assets/models/map/hradec_mapa.glb", {
    recenter = true,   -- scanned data sits far from the origin
    scale    = 10.0,
})

Raises a Lua error the script can see if the file is missing, is not glTF, or requires an unsupported extension. Skinning, morph targets, animation, sparse accessors and Draco compression are not supported; anything else it cannot use is warned about once and skipped.

recenter is worth reaching for on scanned or geo-referenced data: it usually sits hundreds of units from the origin, which makes every camera distance and clip plane meaningless until it is moved back.

collision costs about 36 bytes per triangle and a moment of load time to index; turn it off for a model nothing has to stand on or shoot at. It is what model:groundHeight and model:raycast read.

Engine.texture

Loads PNG, JPEG, BMP, TGA, GIF or HDR. Cached by path, mipmapped, anisotropically filtered.

= true. Leave it on for colour. Pass false for data textures — normal maps, roughness, masks — or they come out wrong.

Engine.shader

Engine.shader.load(vertexPath, fragmentPath)Shader

Compiles, links and caches. Asking for the same pair twice returns the same shader.

self.shader = Engine.shader.load(
    "assets/shaders/basic.vert",
    "assets/shaders/basic.frag")

Recompiles every cached file-backed shader and returns how many succeeded. One that fails to compile keeps its old program, so a syntax error leaves the frame drawing.

Engine.renderer

The one way onto the screen. A script never touches OpenGL; it queues a description and C++ draws the whole frame once every script has had its say.

Engine.renderer.submit(call)number

Queues one draw call, or one per part for a model, and returns how many were queued. Call it from draw().

Exactly one of mesh or model is required — unless fullscreen is set, which brings its own geometry — and shader always is. A missing one is a Lua error with a traceback rather than a silent skip — a submit with a typo in it is a bug in the scene.

function scene:draw()
    Engine.renderer.submit({
        model = self.map,
        shader = self.shader,
    })

    local p = self.player.position
    Engine.renderer.submit({
        mesh = self.player.mesh,
        shader = self.shader,
        position = { p.x, p.y, p.z },
        scale = self.player.size,
        color = { 0.85, 0.35, 0.25 },
    })
end
Fullscreen passesno geometry

A fullscreen call draws one triangle big enough to cover the screen, built inside the vertex shader out of gl_VertexID — there is no mesh, no model matrix and no material. assets/shaders/universal-fullscreen.vert is that vertex shader; pair it with whatever fragment shader the effect needs.

The three passes are drawn in a fixed order that the batching sort cannot cross: background, then world, then overlay. Background and overlay are not depth-tested, so a sky can never occlude the scene and an overlay is never occluded by it. Submission order within a pass does not matter.

function scene:init()
    self.skyShader = Engine.shader.load(
        "assets/shaders/universal-fullscreen.vert",
        "assets/shaders/skybox.frag")
end

function scene:draw()
    Engine.renderer.submit({ shader = self.skyShader, fullscreen = true })
    Engine.renderer.submit({ model = self.map, shader = self.shader })
end

Wireframe skips fullscreen passes entirely: a sky drawn as three lines across the screen is noise, and the point of a wireframe is to see the geometry against an empty background.

Shader uniforms the engine supplies

Every one of these is written only if the shader declares it, so a shader takes what it needs and is never warned about the rest. Bound once per program per frame.

UniformWhat it is
uView, uProjectionmat4 — the active camera's matrices
uCameraPositionvec3 — the eye, in world space
invView, invProjectionmat4 — their inverses, for rebuilding a view ray per pixel
uModel, uNormalMatrixper draw call; not sent to a fullscreen pass
uBaseColor, uAlpha, uHasTexture, uBaseColorTexturethe material; not sent to a fullscreen pass

The inverse pair is what a sky is made of: unproject a clip-space corner with invProjection to get a direction in view space, rotate it into the world with invView, and every pixel knows which way it is looking.

vec4 clip = vec4(uv * 2.0 - 1.0, 1.0, 1.0);
vec4 view = invProjection * clip;
vec3 rayDir = normalize(vec3(invView * vec4(view.xy, -1.0, 0.0)));
Engine.renderer.setCamera(camera)

Sets the EngineCamera whose matrices every shader is fed. camera.lua calls this from activate().

Engine.renderer.clearColor(r, g, b, a)

Four separate numbers, not a table. a defaults to 1.

Engine.renderer.stats()table

Counters for the last frame that was actually drawn: drawCalls, triangles, shaderBinds, textureBinds. Safe to read from update(), which runs before this frame's draw.

local s = Engine.renderer.stats()
Engine.window.setTitle(string.format("%d draws | %d tris", s.drawCalls, s.triangles))

Renderer state outlives a script reload. The clear colour, the active camera and the wireframe flag all survive an edit. A scene should set what it wants in init() rather than assume a fresh renderer.

model:groundHeight(x, z, fromY)number or nil

Height of the highest surface at (x, z) that is at or below fromY, which defaults to just above the model. nil where there is nothing underfoot: past the edge of the map, or over a hole in the mesh.

Pass fromY as the feet plus whatever counts as a step, and a body climbs kerbs without ever being yanked up onto a roof it is walking under. It is one downward ray against a uniform grid over XZ, so calling it once or twice per frame per character costs nothing worth measuring.

-- one body, standing on the terrain rather than on the bounding box
local ground = self.map:groundHeight(p.x, p.z, p.y + stepHeight)
if ground and p.y - ground <= stepHeight then
    p.y = ground
end
model:raycast(ox, oy, oz, dx, dy, dz, maxDistance)table or nil

Closest hit along the ray, or nil for a miss. The direction need not be normalised; maxDistance defaults to unbounded. Triangles are two-sided and the returned normal always faces back along the ray, because geometry out of a scan is not reliably wound one way.

local hit = self.map:raycast(x, y, z, fx, fy, fz, 500)
if hit then
    -- hit.x, hit.y, hit.z, hit.distance, hit.normal.x/.y/.z
    Engine.log(string.format("hit at %.1f units", hit.distance))
end

Both read the model's own coordinates. A model drawn at an offset with position in submit is walked on where it is not drawn — keep a map that carries collision at the origin, or subtract the offset yourself before querying.

Script layout

Everything under src/gameplay/ is scanned on load and on save. A file is a scene if it returns a table with init, update, draw or shutdown — the engine calls those every frame. Everything else is a library the scenes require.

gameplay/
  scene.lua              -- the frame script: loads, wires, and little else
  config.lua             -- every tunable number and key binding
  entities/player.lua    -- a body: movement, gravity, standing on ground
  lib/camera.lua         -- controls around an EngineCamera
  lib/input.lua          -- actions, edge detection, axes
  lib/class.lua          -- the class boilerplate, once
  lib/devtools.lua       -- fps in the title bar, wireframe toggle

Subdirectories are required by dotted path — require("lib.input"), require("entities.player") — and hot-reload the same as a file at the top level.

A library with an update would be mistaken for a scene and run as a frame script. Set library = true on the returned table to opt out. A class built with lib/class.lua needs no flag: __index pointing at itself already tells the engine those are instance methods, not hooks.

config.lua

One table of numbers and key bindings, required by everything else. Nothing outside it holds a speed, a height or a key name, so changing how the game feels never means reading the logic.

Gameplay values are written in metres and seconds. The map is modelled in metres and scaled on load, so unitsPerMetre is the one conversion, applied when an object is built and never thought about again. Write gravity = 9.81, not 98.1.

config.unitsPerMetre = 10.0

config.player = {
    height     = 1.8,   -- m
    walkSpeed  = 4.0,   -- m/s
    gravity    = 9.81,  -- m/s^2
    jumpHeight = 0.6,   -- m, the apex of a standing jump
    stepHeight = 0.5,   -- m, what counts as a kerb and not a wall
}

lib/input.lua

Input as actions rather than keys, plus the edge detection every toggle needs. require("lib.input").

Bind once from config.keys, then call update() at the top of the scene's frame so everything below reads one consistent snapshot. A binding may be a single key or a list, in which case any of them counts.

local Input = require("lib.input")

function scene:init()
    Input.bind(config.keys)   -- { jump = "space", orbitLeft = { "left", "a" }, ... }
end

function scene:update(dt)
    Input.update()            -- first, before anything reads
    if Input.pressed("quit") then Engine.window.close() end
end
FunctionReturns
Input.bind(keymap)binds actions to keys, seeding both frames of state
Input.update()samples every bound action once
Input.down(action)boolean — held right now
Input.pressed(action)boolean — went down this frame, and only this frame
Input.released(action)boolean — came up this frame
Input.axis(negative, positive)-1, 0 or +1 — holding both is a standstill
Input.keyFor(action)string — for help text that cannot drift from the bindings

Input.pressed is the point of the module: a toggle read with Engine.input.key fires every frame the key is held, so each one used to carry its own wasDown field to compare against. That bookkeeping now happens once, for every action.

lib/class.lua

The three lines every class was repeating. require("lib.class") returns a function that makes one.

local class = require("lib.class")
local Player = class("Player")

function Player.new(spec)
    return setmetatable({ health = spec.health }, Player)
end

function Player:update(dt) end   -- an instance method, not a frame hook

return Player

The __index it sets is also how the engine tells a class from a scene, so a class made this way is never mistaken for something to run every frame.

camera:frame(model, options)

Points the camera at a model and backs off until the whole thing fits, then sizes the clip planes and movement speeds to match. Without it a thousand-unit map is either inside-out or entirely behind the far plane.

The fit is solved per bounding-box corner against both the vertical and horizontal field of view. A bounding sphere would be simpler, but a map is a wide flat plate — its sphere is twice the size of anything on screen.

yaw, pitch
degrees to approach from = 45, 35
distance
multiplier on the fitted distance = 1.05. Below 1 crops.
local Camera = require("lib.camera")

self.camera = Camera.new({ fov = 55, mode = "orbit" })
self.camera:frame(self.map, { pitch = 25 })
self.camera:activate()
camera:update(dt)

Runs the control scheme for the current mode. Call it once per frame from the scene — nothing calls it for you, because lib/camera.lua is a library.

Orbit: drag or arrows/WASD to swing around the pivot, Q/E to pull in and out. Fly: drag to look, WASD to move, space and shift for up and down.

Things that bite

Every one of these has already cost someone an afternoon.

Engine.log joins, it does not format

Placeholders come out as literal text with the arguments tacked on after a tab.

Engine.log("health=%d", 100) --> health=%d 100 Engine.log(string.format("health=%d", 100))

Loader options go in one table

A second table is just an extra argument nothing reads, and the silence looks exactly like it worked.

Engine.model.load(path, { recenter = true }, { scale = 10 }) Engine.model.load(path, { recenter = true, scale = 10 })

Scale at load time, not at submit time

camera:frame fits against the model's bounds, and bounds know nothing about a scale applied when the call is submitted. Scale in the options and the camera agrees with what is drawn; scale at submit and it frames a model ten times smaller than the one on screen.

Window queries are functions

Without the parentheses you get the function itself, which is truthy and useless in arithmetic.

local a = Engine.window.aspect local a = Engine.window.aspect()

A class file never runs as a scene

Writing Player.__index = Player marks the table as a class, so its init, update and draw belong to instances. The scene that owns the object is what drives it — nothing calls those hooks for you.

function scene:update(dt) self.player:update(dt) end

And the file has to end in return Player, or require hands back true and the first index into it is an error.

Don't size things off the map

A player is however tall a player is, whatever happens to be around it. Deriving its size from map:radius() is what turns a person into a tower block. Pick real units and stay in them.

Load in init(), never in update()

Engine.model.load and Engine.texture.load are synchronous. They are cached, so a stray call in update() will not re-read the file — but the first one still stalls the frame it happens in.
